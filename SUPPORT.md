# Support

## Where to ask

- Use GitHub Issues for reproducible bugs and scoped feature requests.
- Use private contact with the maintainer for security vulnerabilities or sensitive matters.
- Use the README and docs/ first for setup and configuration questions.

## What to include in a bug report

- Browser and operating system.
- Steps to reproduce.
- Expected and actual behavior.
- Relevant console or network error text.
- Whether the issue occurs with a fresh clone and a valid local configuration.
- A screenshot when it clarifies a visual issue.

## What not to include

Never post API keys, access tokens, passwords, private account details, or personal information. Redact request URLs if they contain credentials in query parameters.

## Response expectations

This is a small maintained project and not a commercial support service. Response times are not guaranteed. Clear, reproducible reports are easier to investigate than general statements that the application is broken.
